\section{Feature Statements}
\label{sec:feature-statement}

This section summarizes the main characteristics of \SPHINCSA\ in the categories requested by the call.

\paragraph{Innovativeness.}
Kylin introduces \WOTSCS, a constant-sum, size-optimal encoding for Winternitz-type one-time signatures, replaces the bottom few-time layer with BPORS+FP, and combines both with Diverse Layer Heights in the hypertree parameter search. These changes improve the signature-size and hash-call trade-off while preserving the conservative hash-based design line.

\paragraph{Simplicity.}
The scheme stays within the well-understood family of stateless hash-based signatures. Its core ingredients are tweakable hash functions, a one-time signature layer, BPORS+FP as the few-time layer, and a hypertree, with no lattice, code, or multivariate algebraic structure.

\paragraph{Flexibility.}
The parameters $(n,w,h,d,K,B,t,k,m_{\max})$ allow the construction to trade signature size, signing time, and verification time. The primary submission fixes the three \texttt{Kylin-128}, \texttt{Kylin-256}, and \texttt{Kylin-512} profiles, while the appendix records additional $q=2^{24}$ profiles for lower signing-budget scenarios.

\paragraph{Compatibility.}
The packaged code follows the NGCC SIG API and routes hash/XOF calls through the ICCS auxiliary functions. The public workflow remains the conventional key-generation, signing, and verification interface. Because \WOTSCS\ replaces \WOTSP, Kylin is not byte-for-byte compatible with the original \SPHINCSP\ formats.

\paragraph{Extensibility.}
The construction is modular: replacing the hash/XOF instantiation or retuning the parameter set does not change the top-level signature workflow. The current submission, however, only claims digital-signature functionality.

\paragraph{Implementation performance advantages.}
The repository provides both ISO C reference implementations and optimized 64-bit PC implementations for the three primary instances. As shown in \cref{tab:kylin-package-bench}, the optimized implementation improves the measured key-generation, signing, and verification times over the reference implementation on the current 64-bit PC benchmark platform.
